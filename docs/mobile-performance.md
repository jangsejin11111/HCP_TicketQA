# 모바일 화면 및 성능 수정 — 2026-11-14

## 원인과 수정

- 표준 viewport 메타 태그 누락: 390px 휴대폰에서도 980px 레이아웃을 사용했고, 게임 영역이 560×2120으로 계산됨. device-width viewport, 본문 여백 제거, 동적 뷰포트 높이(100dvh) 적용.
- render마다 WebGLRenderer.setPixelRatio 호출: 내부 setSize를 통해 매 프레임 캔버스 버퍼 크기를 다시 설정함. 너비/높이/픽셀비 변경 시에만 갱신.
- 모바일의 큰 그리기 버퍼와 촘촘한 지형 주사선: 터치 기기 픽셀비 상한 1.5, 안티앨리어싱 끄기, 지형 행 간격 3px 적용. 글자 지형이 기존보다 다소 부드럽게 보일 수 있음.
- 모바일 그리기 30fps 상한. 이동/입력/상태 업데이트는 requestAnimationFrame에 유지하여 게임 속도를 의도적으로 늦추지 않음.
- 숨겨진 탭의 프레임 작업 중단. QA 표시 버튼을 아래 조작 안내와 겹치지 않게 위로 이동. 짧은 화면에서 수집 안내를 스크롤할 수 있게 수정.

## 비교 결과

Chrome headless, 390×844, DPR 3, 터치 에뮬레이션, CPU 4배 감속. 첫 장 시작 후 2초 준비, 5초 이동 측정. 실제 iOS/Android 기기 측정은 아님.

| 항목 | 수정 전 | 수정 후 |
|---|---:|---:|
| 레이아웃 너비 | 980px | 390px |
| 게임 영역 | 560×2120 | 390×844 |
| WebGL 버퍼 | 1120×4240 | 585×1266 |
| 버퍼 크기 쓰기 횟수 / 5초 | 318 | 0 |
| rAF 콜백 중앙 실행 시간 | 16.2ms | 1.4ms |
| rAF 콜백 95백분위 실행 시간 | 27.6ms | 7.8ms |
| 수정 후 실제 WebGL 그리기 / 5초 | 미계측 | 150 |

콜백 실행 시간은 GPU 완료 시간이나 실제 기기의 전체 프레임 시간을 뜻하지 않음. 수정 후 그리기를 하지 않는 시뮬레이션 전용 프레임도 포함되므로 숫자를 단순한 렌더링 배속으로 해석하면 안 됨.

세로→가로 전환 시 게임 높이가 390px로 갱신됨. JavaScript 예외 없음. 기존 QA 자동 테스트 13개 및 데스크톱 게임 시작/로그인/CSV 다운로드 브라우저 검증 통과.

재검증: `node scripts/mobile-check.mjs`. 결과와 스크린샷은 `test-results/mobile-after.*`에 저장. 실제 휴대폰 Safari/Chrome 및 후반 장 전체 플레이는 별도 확인 필요.


## 갑작스러운 확대 및 잘림 보완

- 터치 핀치와 휠의 암묵적 게임 줌을 제거. 줌은 설정 슬라이더에서만 직접 조절하며, 이야기 연출의 명시적 카메라 줌은 유지.
- 단일 활성 포인터만 이동을 제어. 다중 터치는 이동과 대사 탭을 취소하고, window capture 단계에서 종료/취소를 처리. 캡처 소실, 창 포커스 이탈, 화면 전환에도 이동 상태를 정리.
- 게임 영역 및 프롤로그에 pan-y touch-action을 적용해 세로 스크롤은 유지하면서 브라우저의 연속 탭/핀치 확대를 제한. Safari gesture 기본 동작을 게임 안에서 차단. 문서 전체의 user-scalable=no 제한은 추가하지 않음.
- 모바일 게임 높이를 100svh로 고정해 브라우저 주소창의 접힘/펼침에 따라 카메라 투영 크기가 달라지는 것을 방지. 주소창이 숨겨진 뒤 남는 공간보다 안정적인 장면 크기를 우선.
- 자동 텍스트 확대 제한, 대사·안내·메뉴 폭 제한, 화면 확대 초기화 버튼 추가.
- Chrome 터치 에뮬레이션에서 실제 두 손가락 입력, 연속 탭, 오버레이 pointercancel, blur, 수동 줌/복구, 메뉴 화면 경계 검사 통과. 기존 모바일 30fps 및 버퍼 재설정 0회 유지. QA 테스트 13개와 게임/관리자 브라우저 검사 통과.
- iPhone 카카오톡 WebView와 Safari 실기기는 직접 검증하지 못함. 사진만으로 해당 순간의 브라우저 배율이나 터치 순서를 확정할 수는 없음.
