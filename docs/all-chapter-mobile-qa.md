# 모든 장 모바일 회귀 점검 — 2026-11-14

## 수정 내용

- 5장 흔들림 및 13장 압축 연출 등에서 설정 메뉴까지 움직이던 구조 수정. 메뉴를 변형되는 장면 밖에 배치.
- 9장 강제 카메라 줌이 매 프레임 사용자의 축소/초기화를 덮어쓰던 문제 수정. 수동 조절은 해당 장이 끝날 때까지 우선하며 다음 장에서 해제.
- 연출 줌을 목표 배율로 부드럽게 보간. 장 전환 시 배율, 터치 상태와 장면 CSS 변형 초기화.
- 긴 대사는 스크롤 가능하게 제한하고 선택지와 영역 분리. 320px 세로 화면과 가로 화면, 최대 글자 크기 확인.
- 장 전환 시 장면에서 제거된 geometry/material/texture와 렌더 목록 정리. 현재 장에서 사용하는 공유 자원은 유지.
- 모바일 소 모델의 세분화 감소 및 geometry 공유. 폐공장 덩굴의 가지·잎·생성 수 감소, 도주하는 소와 항구 배경 군중 수 감소. 진행에 필요한 경로와 선택지는 유지.

## 검사 방법과 범위

`node scripts/chapters-check.mjs clone-poem-game.html final`

Chrome 모바일 에뮬레이션 390×844, DPR 3, 터치, CPU 4배 감속. 1~15장 진입 및 10개 추가 체크포인트(동굴 조명, 터널 접근, 계류장 이미지, 폐공장 내부, 매립지 도주/바퀴 파손, 도시 창문/트럭, 항구 대기, 바다 압축, 마지막 장 당기기).
각 구간에서 JS 예외, 수동 0.8배 유지, 1배 초기화 유지, 장면 확대 중 메뉴 경계, 가로 전환의 가로 넘침을 검사. 같은 페이지에서 19회 장 전환과 재진입도 별도 검사.

`node scripts/dialogue-check.mjs`: 320×568 및 844×390, 글자 26px, 긴 대사 스크롤 및 선택지 분리.
`node scripts/mobile-check.mjs`: 다중 터치, 연속 탭, 포인터 취소, 포커스 이탈, 줌 초기화, 버퍼 재할당 검사.
`npm test` 및 `npm run test:browser`: QA 수집/관리자/CSV 회귀 검사.

원시 결과와 캡처는 프로젝트의 `test-results/`에 저장하며 커밋하지 않음. QA 서버에는 동의 거부 상태로 실행해 테스트 데이터를 추가하지 않음.

## 해석상 한계

모든 장의 시작과 위 체크포인트를 자동 검사한 결과이며, 모든 대사 분기를 30분 동안 실제 휴대폰에서 완주한 검사는 아님. iPhone Safari/카카오톡 WebView의 주소창·키보드·메모리 제약은 실기기 확인이 필요함.
초기 장면 생성과 셰이더 준비의 긴 작업은 여전히 관측됨. 첫 로딩의 일시 정지까지 없다고 보장할 수 없음. rAF 콜백 시간은 GPU 완료 시간이나 실기기 전체 프레임 시간이 아님.

## 확인 결과

25개 구간과 19회 장 전환 검사 통과. 모든 구간에서 수동 0.8배와 초기화 1배 유지, 메뉴 화면 경계 및 가로 넘침 검사 통과. JavaScript 예외 없음. 긴 대사 검사, 터치 회귀 검사, QA 단위 테스트 13개와 관리자 CSV 브라우저 검사 통과.

폐공장 내부 표본의 표시 삼각형은 약 230만 → 80만으로 감소(약 65%). 동일 장 재진입 시 8장 geometry 53/texture 1, 9장 geometry 208/texture 2로 반복 후 증가 없음. 전체 메모리 누수가 없음을 증명하는 측정은 아님. 초기 장면 생성 중 최대 약 2.1초의 긴 작업이 있어 저사양 기기 첫 진입 성능은 추가 개선 여지가 있음.
